1. 계정관리 페이지에서 이메일 수정이 가능해야 한다. -> 완료
2. 개발자는 프로그램 변경 리스트 화면에서 입력/수정/삭제가 불가능해야 한다. -> 완료
3. 개발자는 부서이동자 월간 모니터링 화면에서(일간은 제외) 입력/수정/삭제가 불가능해야 한다. -> 완료
4. 개발자는 부서이동자 월간 모니터링 화면에서 월간 조회 실행이 불가능해야 한다. -> 완료
5. 개발자는 부서이동자 일간 모니터링 화면에서 일간 배치 실행이 불가능해야 한다. -> 완료
6. 개발자는 DDL 모니터링 화면에서 입력/수정/삭제가 불가능해야 한다. -> 완료
7. 개발자는 DML 모니터링 담당자화면에서 입력/수정/삭제가 불가능해야 한다. -> 완료
8. DML, DDL 페이지에서 CSV 업로드는 운영자만 가능하다. -> 완료
9. 운영자도 검토수행자와 똑같이 부서이동자 일간 모니터링 화면에서 유지/회수 처리가 가능해야한다.
10. 부서이동자 월간 모니터링 화면에서 유지/회수 처리 버튼은 권한이 없어도 보여야한다. 다만, 권한이 없으면 기능이 동작하지 않는다.
11. 입력/수정/삭제가 불가능하다는 건 조회는 가능해야 한다는 것을 의미한다.
12. 버튼 형태의 실행이 불가능하다는 건 버튼 자체는 보이지만 기능이 동작하지 않음을 의미한다.
13. 역할에 따라 권한이 없는 기능을 실행하면 권한이 부족하니 관리자에게 문의하라는 메시지 알람이 떠야한다. (페이지 접속권한이 아닌 페이지 내의 특정 기능 권한 부족시에는 에러페이지가 아니라 현재 상태에서 메시지 알람만 떠야함.) -> 완료
14. 계정관리 페이지 등 페이지 자체에 대한 접속이 불가한 사용자에게는 권한이 부족하니 관리자에게 문의하라는 화면이 떠야한다.(현재는 json형태이며 페이지가 존재하지 않음) -> 완료
15. 조회자(viewer)권한을 추가한다. 조회자는 개발자 권한에서 DML 개발자화면 입력/수정/삭제 불가하고, 부서이동자 일간 모니터링 화면에서 입력/수정/삭제가 불가해야한다. -> 완료
16. 회원가입 시 사용자는 조회자(viewer)로만 가입할 수 있으며, 4가지 역할에 대해 알고 있어서 다른 역할 부여를 받으려면 문의가 필요함을 알려야한다.
로그인 페이지에는 조회자를 추가하여 4가지 역할이 존재한다는 것을 알려야 한다. -> 완료


[추가]
1. 로그인화면에서 조회자가 내려가있는데 검토수행자를 검토자로 바꾸고 조회자도 1줄로 나오게 표시
2. 회원가입화면에서도 조회자가 내려가있는데 검토수행자를 검토자로 바꾸고 조회자도 1줄로 나오게 표시
3. DML, DDL 페이지 CSV 업로드는 운영자만 가능하다.(맞는지 검증필요) CSV 업로드 버튼 클릭 시 탐색기가 열리는데 기본적으로 운영자를 제외하고는(즉, 권한이 없다면) 아예 파일탐색기창 자체를 뜨지 않게해야한다.
4. 프로그램변경리스트 시스템별 엑셀버튼, 부서이동자 월간화면 엑셀 버튼, DML, DDL 엑셀다운로드 버튼 클릭 시 다운로드 중인지 확인이 안됨. 버튼에 다운로드되고 있다는 걸 표시해줘야할듯.(CSV 업로드 시 업로드 중... 이런식으로 뜨던데 이런 식으로)
5. 계정관리 페이지 - 계정 목록에서 기본은 조회용으로 한다. 변경하는 버튼 클릭 시 이름과 이메일이 수정 가능하도록 입력필드로 바뀜
다시 말하자면, 관리칼럼은 조회모드든 변경모드든 동일하고, 변경모드에서는 이름/이메일이 입력가능하도록 바뀐다. 조회모드에선 이름/이메일이 입력필드 없이 내용만 보여야한다.
6. DML, DDL페이지 화면에서 적용 버튼을 누르면 수정된다는 문구가 변경되어야 한다.(현재 적용 버튼이 존재하지 않음.)
7. 개발자가 DML 담당자 화면에서 적용이 가능한데, 역할상 developer는 담당자화면 입력/수정/삭제가 불가여야함.(검증필요)
8. DDL화면, DML담당자화면, DML개발자화면에서 저장 실패랑 권한 부족이 동시에 뜨는데 권한부족만 뜨면됨.
9. 계정관리 화면에서 계정 생성 설명에 초기 비밀번호가 무엇인지 적어야한다.(config값을 자동으로 읽거나 변경이 많이 필요하면 현재 값으로 그냥 하드코딩)
