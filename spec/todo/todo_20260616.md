1. (개발자화면) SR없음 표시로 행 높이가 너무 큼. SR번호가 없더라도 입력만 하면 상태는 무조건 적용완료로만 나옴
-> SR없음/SR존재 표시를 빼고 상태 칼럼을 3가지 상태로 표시해야할 것 같음. 
SR존재여부 - 없으면 입력하지 않은 상태와 동일(즉, 미매핑=미입력), 있으면 정상여부에 따라 정상/비정상 판단(pcl_judger.py 참고)
3가지 상태 : SR없음orSR미입력(미적용), SR존재+비정상(비정상), SR존재+정상(정상)
(1) SR번호가 없거나 SR번호를 미입력 - 빨간색, 기존 미적용 건수로 잡는 것 동일. 상태를 빨간색으로 "미적용"
(2) SR번호 존재+비정상 - 노란색, 기존 적용완료건수로 잡음.(미적용이아니므로), 상태는 노란색으로 "비정상"
(3) SR존재+정상 - 초록색, 적용완료건수로 잡고, 상태는 초록색으로 "정상"
* 정상/비정상 여부는 pcl_judger.py 확인 - 아마 작업승인일 이후 DML실행, 작업구분 긴급인 경우 DML실행 이후 5일 이내에 SR종료일(코드랑 불일치 시에는 알려줘. 뭐가 맞는지 확인해야돼)
* 기존 KPI, 개발자진행현황, 진행률 등에 출력되는 적용완료/미적용은 그대로 유지. 새로운 화면 기준으로 빨간색은 미적용, 노란색,초록색은 적용완료라고 봐야됨. - 이해안되면 물어봐. 다시말하자면 적용완료라는 것은 미매핑,미입력이 아닌 모든 것을 말함.
* 엑셀출력은 변경할 필요없음.
2. (담당자화면) 개발자화면과 마찬가지로 상태를 3가지 상태로 구분 필요.
3. 개발자,담당자화면에 각각 상태에 대한 간단한 설명을 화면에 보이게 해줘.(빨간색은 미매핑or미입력이다 뭐이런식으로 알아서해줘.)
4. (담당자화면) 엑셀버튼 클릭했을 때 데이터가 없으면 에러페이지로 넘어가는데 다른 방식으로 에러처리해줘야됨.

-> 상단 KPI(각 탭들보다 윗부분)에 DML과 같이 적용완료/미적용이 몇건인지 등을 확인할 수 있어야한다. 
* KPI에서 보여져야할 내용 : 부서이동자 리스트 건수, PMS,HR,전자조달 전체 건수 및 미적용 건수, 진행률(DML 참고)
