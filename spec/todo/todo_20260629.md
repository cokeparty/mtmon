
[대시보드]
1. 최상단 4개 카드에서 프로그램변경, 데이터변경, 프로시저는 정상/비정상/미적용 순으로  상태가 나와야하며 비정상의 색이 주황색이고 미적용이 빨간색이다. 부서이동자는 현재와 같이 적용/미적용이 나와야하지만 미적용은 빨간색이다.
2. 상단 원그래프에서 프로그램변경과 DML 사이에 부서이동자를 추가하고 건수를 합산하며 부서이동자 적용인 경우를 정상, 미적용인 경우 미적용으로 카운트한다.

[부서이동자]
1. 일간화면에서의 데이터는 결국 월간화면에서의 데이터, SR번호가 일치할 수 밖에 없는데, 문제는 일간화면은 7일뷰를 조회하고 매일 배치를 돌리며 월간화면은 1달뷰를 조회하고 다음달이 되어서야 데이터가 생김.
월간 배치를 돌렸을 때, 일간데이터에 들어간 SR번호를 자동으로 매핑하도록 하고 싶은데 현재 DB 구조를 파악해서 가능한지 확인

[계정]
1. 계정관리 페이지를 추가하여 계정을 생성, 조회할 수 있고 권한을 부여,수정할 수 있게 한다. 비밀번호는 관리자가 입력하지 않고, 생성 시 초기 비밀번호를 자동으로 부여하며, 이후에도 관리자가 비밀번호 초기화를 할 수 있다. 초기비밀번호는 Mtmon12#이고, .env에 작성하도록한다.
2. (수정금지) 나중에 역할-권한 체계를 만들어, 계정 또는 권한관리 페이지에서 역할을 편집하여 권한을 추가할 수 있도록 할 예정이다.
권한은 데이터변경 페이지 CSV업로드 권한, 프로시저 모니터링 수정권한, 프로그램변경 모니터링 조회권한 등 상식적으로 구분되어야할 역할을 구분할 예정이다. 이 경우에 전체 시스템에서 어떤 것을 권한으로 만들 수 있을지 예상 권한을 보여줘.

[회원가입]
1. 권한체크하는 부분에서 검토수행자가 밑으로 내려가서 보임. 한줄로 권한 다 보이게 변경.



[DDL]
1. DML과 같이 사유미입력 KPI가 존재해야하고, 위험 DDL KPI는 제거한다. 
사유미입력이란, DML과 같이 비정상인 경우에 사유가 미입력된 것의 건수를 의미함.
2. DML과 같이 사유입력하고 확인할 수 있으며, 수정가능한 버튼이 필요함.
3. 엑셀출력시, 모니터링결과 칼럼에서 DML과 같이 정상이면 특이사항 없음, 비정상인데 사유입력 시 그 사유, 비정상인데 사유 미입력 시 사유 입력이 필요하다는 말이 적혀있어야함.
미적용 시에는 SR번호 없음.
4. 엑셀 출력 시, 비정상이 빨간색인데 정상은 초록색, 비정상은 노란색, 미적용은 빨간색으로 적용한다.
5. 엑셀에는 프로시저변경요청승인,사용자테스트,이관전승인,개발자,이관자,검토수행자, 모니터링결과("모니터링 결과" 라고 되어있는데 띄어쓰기제거) 칼럼이 존재하는데 웹상에서는 보이지않음. 그것을 웹상에서 입력가능하게 추가하고, 프로그램변경 모니터링을 참고하여 디폴트 값을 아래와 같이 설정함.
프로시저변경요청승인 : O
사용자테스트 : O
이관전승인 : 작업승인일 이후 SQL실행했으면 O, 아니면 X(작업승인일<=요청시각)
개발자 : 빈값
이관자 : 이기헌
검토수행자 : 노광환
그리고 프로그램변경 모니터링과 같이 방금 추가된 칼럼들에 입력 시 입력되었다는 표시와, 입력창 색이 행 색과 동일하게 변경되어야하고 빈값입력시 흰색으로 돌아가야함.
=> 엑셀출력에도 내용들어가게 업데이트

[DDL, DML공통]
1. 자동매핑 버튼이 불필요하던데 실제로 불필요할지 확인해주고 삭제할 것. 

[DML]
1. DML여부 칼럼은 비DML로 버튼 클릭 시 초록색 타원형의 "DML 아님"으로 변경되는데 일관성을 위해 "비DML로" 버튼 클릭 시 "DML로" 버튼으로 변경하며 형태는 비DML로 와 동일하고 색상은 초록색으로 하며 클릭했을 때 원상복구되고 따라서 되돌리기 버튼이 불필요함.
2. 담당자화면에서도 개발자화면과 같이 SR입력이 가능하고, DML여부 선택(1번적용된), 비정상 상태 사유 입력가능, 
3. [담당자화면]개발자화면에서 비DML로 버튼 클릭한 뒤 담당자화면에서 나오지않음.
마찬가지로, SR번호부터 SR종료일까지의 칼럼이 DML이 아님을 표시해야함.
4. 개발자화면에서 사유입력 후 지우고 나면 KPI는 사유미입력으로 카운트 되는데(맞음) 엑셀 출력 시에 사유 입력이 필요하다는 메시지가 모니터링결과에 안보임.
=> 적용 이후
[DML]
1. 담당자화면에서는 개발자화면과 달리 DML이 아닌 경우, SR번호 입력창이 안보임 -> 개발자화면과 동일하게 SR입력창에서 글자가 적혀있고, 초록색으로 변경되어야 하며, 글자수정못하게 해야한다.
2. 담당자화면은 개발자화면과 같이 DML이 아닌 경우, "DML이 아님" 이라고 표시되어야함.현재는 "DML 아님"으로 표시됨. 색도 현재는 초록색인데 검정색으로 되어있어야함.
3. 담당자화면에서 상세행도 볼수 있어야하며, 개발자화면과 동일하게 나와야함.
4. 담당자화면 행 높이가 개발자화면과 다름. 개발자화면과 동일한 높이를 가져야함.
[DDL]
1. 사유미입력 KPI는 미적용과 적용완료 사이에 존재해야하며, 노란색이어야함.(DML과 똑같이하라니까 )
2. 이관전승인 칼럼이 SR번호 입력해도 변경되지 않음. 이관전승인 칼럼은 작업승인일과 요청시각을 비교해서 항상 최신화되어 있어야한다.

[DDL]
1. KPI에서 SR번호 입력하면 33%로 나오다가 새로고침하면 100%가 됨. 그리고 전체 개수가 보이는 건 1갠데, 3개 표시라고 나옴. 확인필요.
2. 이관전승인 칼럼은 작업승인일이 없으면 당연히 X가 나와야해. 그런데 현재는 잘못된 SR번호를 입력해도 이관전승인이 O로 표시됨.
-> 프로그램변경 리스트에서도 이게 적용되어 있는지 확인하고 안되어있으면 프로그램변경 리스트도 변경필요.
3. DDL 상세 행 버튼 클릭 시 나오는 일명 멤버 행은 DML의 멤버행과 높이가 같아야 하며, DML의 경우는 멤버마다 아래에 줄이 있는데 DDL은 없으니 DML과 같이 수정필요.(멤버행 디자인을 DML과 동일하게)
4. 위험 DDL만 버튼은 불필요하니 지워줘. 그리고 혹시 DROP이나 TRUNCATE가 행 색을 변경하거나 하지는 않는지 확인해줘. 만약 한다면 불필요하니 제거필요. 
5. DML과 같이 미적용/비정상/정상 설명 부분을 박스로 감싸줘.

[DDL]
1. 상세 버튼 클릭 시, 쿼리만 조회되고 있는데 그룹 안의 각각의 SQL에 대한 정보를 알아야 하므로, DML과 같이 요청시각, 쿼리, SR번호를 확인가능해야함.
[DDL&DML공통]
1. DML, DDL 모두 그룹 상세 행 버튼 클릭 시 상세 행이 나오는데, 상세 행의 쿼리는 전체를 확인할 수 있어야함. 따라서 상세 쿼리 버튼 클릭 시 전체 쿼리를 확인할 수 있게 모달로 띄우든 해야할 것.

[계정]
1. 조회자 권한을 추가(viewer)하고, 모든 페이지에 대해 조회만 가능해야 한다.(업로드 불가, SR입력불가, 적용취소버튼 클릭 불가, 회수유지 버튼 클릭 불가, 부서이동자 배치 버튼 클릭 불가 등)
2. 회원가입을 하면 viewer 권한이 부여되며, 권한을 변경하는 것은 계정관리에서 하도록 한다.(회원가입 페이지에서 역할 선택 버튼 제거)
